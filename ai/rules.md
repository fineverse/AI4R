# AI 行为规范

> **结构（2026-10-06 重构）**：本文件只保留可执行规则；起因、事故与历史演化叙事在 [lessons.md](lessons.md)。规则应描述目标和安全边界，不绑定某个智能体产品的工具名或审批模型。

## 语言

默认使用中文。

## 证据等级

**本表是工作空间内证据等级的唯一定义处**；`shared/research-workflow.md` 与 `ai/templates.md` 只引用、不重复。区分以下等级，不得混淆：

| 等级 | 含义 | 示例 |
|---|---|---|
| 元数据 | 仅从 DOI/OpenAlex/Crossref 获取标题、作者、年份 | "该论文发表于 IEEE TIV 2024" |
| 摘要 | 已读出版社或 arXiv 摘要 | "摘要声称覆盖 270+ 篇论文" |
| 全文 | 已读完整论文文字 | "论文第三章讨论了评价协议" |
| 代码静态检查 | 已查看仓库代码结构和关键文件，未运行 | "损失函数在 `loss.py:45` 定义" |
| 成功运行 | 已在本地成功运行并产生输出 | "在 NAVSIM v1 上复现了表 2 的 L2 误差" |
| 独立复现 | 从零搭建环境并独立验证 | "独立训练并得到与论文一致的结果" |

不得将低等级证据当作高等级使用。没有代码的论文降低对其实现和结果的信任度。**论文表的证据状态列不得使用词表外档位**（历史漂移实例见 [lessons.md](lessons.md) §六）。**例外**：综述类表（如 [`direction/surveys/e2e_ad_surveys.md`](../projects/autonomous-driving/direction/surveys/e2e_ad_surveys.md)）可用"窄词表"（如 `全文目录` / `项目页`），但须在表头声明该表口径。

### "代码静态检查"必须再分三级

同一个"代码静态检查"标签下，核查强度差别很大，**标注时必须带级别**：

| 级别 | 做法 | 能支持什么结论 | 不能支持什么 |
|---|---|---|---|
| **L1 逐文件核验** | 克隆后读关键文件与配置，逐项对齐 `文件:行号` | "论文声称的机制在代码里是否真的实现" | 性能与延迟 |
| **L2 仓库存在性** | 只确认仓库可访问、README 与目录结构 | "有没有官方代码" | 机制是否实现 |
| **L3 API + `raw` 取证（未克隆）** | 走 GitHub trees API + `raw.githubusercontent.com` 逐文件取内容（**不占 API 额度、不占磁盘**），**逐文件比对字节数与树接口** | 与 L1 同级的机制核验（**用于克隆失败的仓库**） | 需要运行才能知道的量 |

**配套事实（写入 `repositories.md`）**：L3 的字节数必须与 trees API 的 `size` 逐一对齐，否则视为取证不完整。**已知克隆会失败的情形**：大仓（>100 MB）、含 LFS 的仓、tarball 在固定字节处截断。

**与质量分档的关系**：证据等级回答"我读到了什么程度"，**质量分档**回答"这篇值不值得读"。判断预印本（无 venue、无引用）时按 [shared/literature-quality.md](../shared/literature-quality.md) 分档（T1–T5）并标注可复核依据。

**⚠ 撞名消歧**："**L2 级别**"（本表的仓库存在性）与 nuScenes 的 "**L2 误差**"（平均位移指标，见 benchmarks.md §2.8）撞名——前者只在**证据等级**语境、后者只在**指标**语境使用；同一句里两者都出现时必须展开全称。

### venue 核验必须三渠道并行

"取不到 venue"常常不是"没有 venue"，而是 **arXiv `comments` 里没写**。三条渠道：

1. arXiv `comments` 字段（注意区分 "**Submitted to** X" = 投稿 与 "Accepted by X" = 录用）
2. OpenAlex 按标题（**匿名查询会 429 限流，需备用渠道**）
3. Crossref 按 DOI 反查

**按标题在 arXiv 找不到时，先怀疑"根本没有 arXiv 版本"**（会议版 / 已撤稿投稿两类实例见 [lessons.md](lessons.md) §三同类教训）→ 去 OpenReview 与出版社目录页反查。

## 子代理纪律

1. 子代理是可选的并行手段，不是所有检索或多文件任务的强制步骤；是否使用以用户要求、当前环境能力、任务可分性和成本为准。
2. 主线程负责目标、证据边界、最终判断与写回。子代理结论必须能定位到文件、代码或来源，主线程在采纳前复核关键证据。
3. 多代理共享工作树时，默认给子代理只读任务。确需写入时，必须事先分配互不重叠的目标路径；无法保证路径隔离时改用 `inbox/` 投递物。
4. 外部取证缓存放 `inbox/scratch/<name>_probe/`；避免重复下载和无边界克隆。全库搜索默认排除 `projects/*/code/repos/`、虚拟环境和 runtime。

## 支线协作纪律

同一工作树中的并行写入是 last-write-wins，Git 不会自动合并两个会话的未提交内容。协作依据是**目标路径所有权**，不是“主线/支线”身份或文件是否已经存在。

1. **写前检查**：运行 `git log --oneline -5` 与 `git status --short`，列出本次目标路径。工作树非空只说明已有改动；先判断是否与目标路径重叠，不因无关改动停工。
2. **路径分配**：并行会话可修改既有文件，但同一时段不得写同一路径。共享入口（README、state、history 索引）原则上由当前任务负责人统一收口。
3. **重叠处理**：目标路径已有归属明确的未提交改动时，不覆盖；选择等待、重新分配路径，或按 [templates.md](templates.md) 写入 `inbox/` 投递物。
4. **提交隔离**：只用 `git add -- <明确路径...>` 暂存本次文件，提交前检查 `git diff --cached`。禁止无路径的 `git add -u`、`git add -A` 或提交整个工作树。
5. **冲突恢复**：先把当前现场复制到 `inbox/scratch/`，再用 `git show <commit>:<path>` 导出已提交版本进行比较。Git 不能找回从未提交且已被覆盖的内容；不得用 `git checkout HEAD -- <file>` 冒充恢复未提交原稿。
6. **投递物归宿**：采纳、否决或搁置后移入 `archive/YYYY-MM-DD-支线交付-<主题>.md`，文件头记录处置结论与整合位置；原始正文不改。
7. `history/CURRENT.md` 只在持续时间较长、确实存在并行写入的研究任务中作为可选软通道，不是每个任务的强制同步位；Git 状态和明确路径分工才是硬边界。

## 文件更新

- 按信息角色更新唯一权威源：`README.md` = 导航与极简摘要，`state.md` = 当前状态与下一步，实验 `protocol.md` = 实验定义，`history.md` / 分卷 = 已发生事件，`index.md` = 内容位置。
- 只有对应角色的事实发生实质变化时才更新该文件；快速维护不强制触碰 README、shared 工具页或所有专题入口。
- README 不保存逐轮正文或重复结论；需要追溯时只指向 state/history。
- **文件尺寸预算**（判定阈值有三条，**任一超限都算超限**）：
  1. `index.md` / `state.md` ≤ **100 行**
  2. **任何文档建议 ≤ 64 KiB**（65536 字节）——这是可扫描性和维护成本控制，不再绑定某个智能体的读取工具；由 `check_links.py` 第 12 项检查。**两线制**：
     - **硬线 64 KiB**：超 = 违规、参与 exit code，**收尾前必须处理**（确实修不完的，按 [workflows.md](workflows.md) §轮次收尾第 7 步在提交信息里记"已知告警"）。
     - **预警线 60 KiB**：进入 = 预警（**只报不阻断**），留约一轮增量余量。
     - **零和编辑纪律（第七十八轮加）**：预警带内的文件，编辑必须**零和或负和**（新增 N 字节须同步删 ≥N 字节）；需要正和追加时，先瘦身腾出空间再追加，或把内容改道到其他文件（先例：`sota-plan` 的结论改落 `recombination-map`）。
     - **超限处理按文件角色分档**（**不一律拆册**）：
       ① **索引/登记类**（`history.md`、`index.md`、`sources.md`、各 README）→ **瘦身**（价值在"可扫"，详情已在别处，压缩为指针），**不拆册**；
       ② **脉络/清单类**（`lineage.md`、`transfer.md`、`code/traces/*`、`papers.md`）→ **拆册**（`X-2.md`，见 [templates.md](templates.md) §分册、编号与更正约定）；
       ③ **决策/交叉引用稠密类**（`sota-plan.md`、`preparation.md`、`judgments.md`）→ **优先瘦身去重**；瘦身后仍超线、且找得到"引用最少"的章节边界时才拆册（错册代价的实例见 [lessons.md](lessons.md) §三.9）。
  3. 论文笔记一篇一文件
- `state.md` 超限有两种形态：**行数超限**（拆出 `history.md`）与**行数合规但体积超限**（拆出 `judgments.md`，`state.md` 只留分组索引）
- 不记录每一句聊天
- 重要结论被修正时保留修正原因和原依据
- 已放弃的 idea 与失败实验保留记录后移入 archive
- **单一事实源**：同一当前事实只允许一处权威副本；历史文件可保留当时说法，但必须有日期或更正指针。证据等级以本文档为准，工作空间组织以 [`shared/workspace-design.md`](../shared/workspace-design.md) 为准；其他文件只写摘要和指针。

## 主动优化

- 发现工作空间结构问题（重复副本、死链、超限文件、状态失真）或效率/产出改进机会时，主动向用户提出优化请求，不等询问
- 用户已确认：此类提议的讨论与执行成本可接受，判断标准只有效率提升与产出提升
- **健康自检**（结构变动后或用户要求时）：审计死链、孤儿文件、`state.md` 失真、超限文件和单一事实源违反。批量改写前记录已有改动并备份目标文件；不要求整个共享工作树为空，但目标路径归属必须明确。

## 跨对话恢复

每次开始工作按 AGENTS.md 指定的入口读取，当前用户指令优先于历史记录。

## 执行与清理纪律

### 只读操作的工具选择

优先使用当前智能体环境提供的专用读取、搜索和文件定位工具。若环境没有对应工具，允许使用只读 shell 命令：搜索优先 `rg`（不可用时用 `grep`），定位文件可用 `find`，分段读取可用 `sed`。命令必须限定在工作空间与本次任务所需路径；不得因为缺少旧环境的特定工具而停止工作，也不得借只读检查扩大到无关目录或输出敏感信息。

（本节的由来与"临时根为何从 `/tmp` 迁回工作空间"的完整教训见 [lessons.md](lessons.md) §二。）

1. **临时产物与耐久资产分开**：可再生的下载片段、解压中间件、探测缓存放 `inbox/scratch/`。虚拟环境、runtime 仓库、checkpoint、数据集和已登记运行缓存属于耐久本地资产，即使暂时位于 scratch 也不得按临时文件清理；阶段 4 完成迁移前尤其如此。
2. **范围最小化**：命令和文件操作只覆盖当前任务所需路径。读取优先专用工具；缺失时可用范围收窄的只读 shell，并使用工具的 `workdir` / `cwd`。
3. **删除与覆盖**：只删除用户明确要求或任务正常产出的确定目标；删除前解析实际路径，避免宽泛目录、未解析变量和危险 glob。能移动到可恢复位置时优先移动。
4. **不可逆操作前备份**：批量改写、文件拆分、迁移或覆盖前，把目标现场复制到 `inbox/scratch/`；完成后至少检查 diff、体积/条数守恒和死链。备份不得与待迁移目标放在同一清理范围。
5. **失败现场可诊断**：重试使用独立输出目录或 run ID，不静默覆盖上一次结果；失败日志保留到结论落盘并完成验证。
6. **可复现脚本入库**：会重复使用或承担研究结论的脚本放 `shared/scripts/`；一次性只读探测可直接使用当前环境工具，不为减少工具调用而强行拼接难审查的长命令。
7. **清理前分类**：清理清单须区分 tracked 文件、临时产物和耐久本地资产。对 tracked 文件用路径级 diff 审查；对工作空间外或体积较大的资产先报告影响与恢复方式。
8. **现有改动优先保护**：共享工作树出现无关未提交修改时保留并绕开；无法绕开才暂停并协调，不使用 reset、checkout 或覆盖写入替别人“清理现场”。
9. **Git 提交按任务分级**：只读审计不提交；快速维护、研究更新和里程碑在用户要求或形成清晰可回退检查点时提交。
   - 暂存只能使用 `git add -- <本次明确路径...>`，随后检查 `git diff --cached`；禁止无路径 `git add -u`、`git add -A`。
   - 提交信息写清“改了什么、为什么”。研究轮可用 `第 N 轮：`；工具或维护任务使用描述性前缀，不占研究轮次。
   - push 是外部发布动作，只有用户明确要求时执行；不得把机器特定代理写成全局必需步骤。
   - `round-N` annotated tag 只用于正式研究里程碑，并在包含该轮内容的 commit 之后创建；随后再运行发布检查。普通维护和实验尝试不打 tag。
10. **危险操作自守**：不执行未经明确授权的 `reset --hard`、`clean -f`、`push --force`、宽泛递归删除或覆盖恢复。发生冲突时先保存现场、比较版本，再选择性应用差异；不要用破坏性命令换取“干净工作树”。
