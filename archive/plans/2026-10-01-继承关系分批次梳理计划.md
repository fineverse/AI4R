## 二、口径（先明确"要梳理什么"）

**定义**：继承关系 = 一个工作的**代码/基线血统**——它建立在哪个前作或代码库之上。
**广义血统**，每条必须标**强度**（四级，由强到弱）：

| 强度 | 含义 | 判据 |
|---|---|---|
| **S1 硬继承** | 类继承 / fork / 代码派生 | `class X(Y)`、fork 记录、逐行对照坐实 |
| **S2 自述派生** | 官方自述基于前作 | README / 论文写 `based on` / `built upon` / `following` |
| **S3 模块复用** | 只搬了部分 | 抄损失函数、vendored 代码、同名锚点/词表 |
| **S4 团队延续** | 仅同团队/同机构 | 无代码证据 → **必须标"推断"** |

**边界（不混入）**：组合关系（模块来自哪篇论文）与主张—代码关系仍归 `code/traces/`；
继承关系只写"整体血统 / 基线来源"。两者在 `world_model_code_traces.md §B`（组合）与
新增的世模继承节之间要划清。

**素材纪律**：只从**已核验**的 `code/traces/*.md` 与已有笔记汇总，**不新增代码阅读**；
缺证据的条目降级为 S4 并标"推断"，**不臆造**。
