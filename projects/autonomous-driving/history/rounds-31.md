# 第三十一轮（笔记「对本项目的意义」节补齐与统一，2026-09-24）

**动因**：`ai/templates.md` 早已把论文笔记的 **`## 对本项目的意义`** 定为**必写**，第二十八轮审计也记下了实况缺口（"47 篇里只有 14 篇有"），但**从未处理**。这一节正是把"读过的论文"变成"可用于 idea 讨论的判断"的那一步——缺了它，47 篇笔记就只是资料，不是消化过的结论。本轮把它从"约定"变成"**事实 + 可自动检查**"。

## 1. 先排除两个误报（避免修错东西）

| 疑点 | 核查结论 |
|---|---|
| 全库引用了 `L101`/`L110`/`L126`… 等 **20+ 个不在 `sources.md` 里的来源编号** | **误报**——这些出现在 `code/repos/` 的第三方 README 里（已克隆仓库的文档）。排除 `code/repos/` 与 `.trae` 后，第一方引用的编号**全部落在已定义集合内**（B001–B013 / C001–C005 / L001–L021 / P001–P006） |
| `P100`（2 处）像是悬空编号 | **误报**——是 **NVIDIA P100 显卡**（`160ms（≈6.3 FPS，P100）`） |

→ **来源编号引用完整性本轮无问题**（这项本身值得保留为一次性抽查口径，但暂不自动化——误报率太高）。

## 2. 真实情况：7 种命名 + 4 篇完全没有 + 5 篇只是粗体 bullet

对 47 篇 `notes/*.md` 逐篇列标题后，实际情况比"只有 14 篇有"更细：

| 形态 | 篇数 | 处理 |
|---|---|---|
| `## 对本项目的意义` | 14 | 不动（含 `（重要）` 括注） |
| `## 对本项目的用途` | 7 | → 统一命名 |
| `## 与本项目的关系` / `（关键）` | 10 | → 统一命名 |
| `## 与 DiffusionDrive 的关系` | 2 | → 统一命名 |
| `## 迁移到自动驾驶（AI 判断）` | 4 | → 统一命名（保留 `（AI 判断）`） |
| `## 迁移到自动驾驶的可行性（AI 判断）` | 4 | → 统一命名（保留 `（AI 判断）`） |
| **只写成"在脉络"节里的粗体 bullet**（`- **对本项目的含义**：…`） | 5 | → **升级为节标题**（E2E-06/08/09/10/11） |
| **完全没有** | 1 | → **补写**（E2E-07 TransFuser） |

**关键发现**：那 5 篇并非"没写"，而是**写成了粗体 bullet**——与第二十八轮修过的"C003 第二册声明了子节却只有粗体标签"是**同一类问题：内容在，锚点不在**。读者与 AI 都定位不到，也没法自动检查。

## 3. 做法

1. **备份**：批量改写前把 47 篇笔记 `cp` 到 `/tmp/ai4r/notes_bak/`（316 KB）
2. **统一命名**：脚本按"长键优先"匹配，27 处标题改为 `## 对本项目的意义`（+ 原括注）；**明确不动** `## 与扩散规划器的关系`、`## 评价协议（本项目…）`——它们是另外的节
3. **升级 5 处粗体 bullet**：把 `- **对本项目的含义**：X` 拆成 `## 对本项目的意义` + 正文 X，原"在脉络"节保留其继承/转折意义/被谁继承三条
4. **补写 1 篇**：E2E-07 TransFuser 的该节从原"被谁继承"bullet 里的"本项目主线都用 TransFuser 主干"提升并扩写为两条直接后果（对比时要控的是 `tf_d_model`/`lidar_seq_len` 而非主干；自建基线沿用它是与榜面对齐的最低成本选择）
5. **顺手统一另一处碎片**：`## 在脉络中的意义` / `## 在脉络中的位置` 两个名字（7 篇）→ 统一为 `## 在脉络中的位置`
6. **加第六项检查**：`notes/*.md` 必须含以 `## 对本项目的意义` 开头的二级标题（允许后缀括注），缺即报错
