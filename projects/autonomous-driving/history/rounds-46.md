# 第四十六轮（2026-09-24）· 把"CSV 是权威源"这条约定锁进机器检查

**动因**：第四十四、四十五两轮把"**声明的计数**"和"**章节引用的可达性**"纳入了机器检查。顺着"还有什么**已被写进约定、但从没被机器核过**"往下问，落到一条工作空间自己声明过的规矩：

> **CSV 是与 markdown 表双表示时的权威源。**

问题在于：**"谁是权威"只在两者一致时才有意义。** 一旦漂移，按 md 读的人和按 CSV 检索的人会看到**两个不同的集合，而且两边都"看起来对"**——死链、计数、章节三类检查**都管不到**这件事（文件都在、链接都对、数字都自洽）。

## 做法

工作空间有 4 对双表示（另有两份 CCF 参考 CSV 是单表示，不在范围内）。逐对比对**两边出现的 ID 集合**：

| 对 | CSV | md |
|---|---|---|
| `e2e_ad_surveys` | 45 | 45 |
| `diffusion_planner_ad` | 34 | 34 |
| `diffusion_planner_surveys` | 15 | 15 |
| `diffusion_planner_embodied` | 28 | 28 |

## 结论

### 1. **4 对全部一致，双向零差**——本轮没修任何错

这是一次**验证**，不是一次修复。但过程中撞到两个**必须记下来的解析陷阱**，否则这个检查会写错：

**① 各 CSV 的列布局不同**：`e2e_ad_surveys.csv` 的 ID 在**第 1 列**、表头还是**小写 `id`**；另外三张的 ID 在第 2 / 第 5 列（首列是"分组"或"综述"）。**按固定列号写会全盘错位。**

**② 只扫"ID 列"会漏掉整整一类**：`diffusion_planner_surveys.csv` 里 **`DP-S13`（待核验条目）不在 ID 列**，而在**段标题行 `E. 待核验,,,,…,DP-S13,…` 的靠后一列**——CSV 把 md 的「§E 待核验」也镜像了，只是形状不同。
> **这个陷阱差点让我得出错误结论**：只扫 ID 列时 CSV 14 条、md 15 条 → 会报"**DP-S13 缺失**"。而实际上 **md 的 §E 待核验里也有 DP-S13，两边是一致的**——差的是我的解析，不是数据。

→ **规则定为：两边都扫"全单元格"**，ID 集合必须完全相同。

### 2. 加了第十项检查「CSV 与 markdown 表的 ID 一致性」

- 对子登记在 `CSV_ID_PAIRS`（4 对 + 各自的 ID 正则）
- **双向都报**："只在 CSV"（md 里没有这一条）与"只在 md"（CSV 里没有这一条）分开列
- 文件缺失也报（`.csv` / `.md` 任一不存在）

**负向测试（两个方向各一次）**：往 CSV 追加一行 `DP-A99` → 报"只在 CSV → ['DP-A99']"；把 md 里的 `DP-A01` 改成 `DP-A88` → 报"只在 md → ['DP-A88']"；均改回后 0 处。

### 3. 与前两轮的关系

| 检查 | 治什么 | 本轮之前是否覆盖 |
|---|---|---|
| 第八项 判断条数一致性 | 同一条信息在**文档内部**的多处声明 | 第四十四轮加 |
| 第九项 声明计数 vs 权威源 | 声明的数字与**文档之外的权威源** | 第四十四轮加 |
| 第五项 章节引用可达性 | **引用指向的章节**存不存在 | 第四十五轮扩 |
| **第十项 CSV 与 md 的 ID 一致性** | **同一份数据的两种表示**是否还是同一份 | **本轮加** |

→ 四项合起来，覆盖了"**同一事实的四种载体**"：正文声明、外部权威源、章节锚点、双表示文件。
