# 第五十四轮（2026-09-28）· 把完整政策分与候选池诊断分开

继续消化路线 B 协议与 NAVSIM 评价实现后，发现仅把 `C_N` 标成“诊断量”还不够：原协议仍把固定候选 0 的完整 EPDMS、已发布策略 EPDMS、逐场景候选 oracle 放在同一组公式中，读者仍可能把它们误当作同一聚合层级。NAVSIM v2 的第二阶段权重以第一阶段输出终点为中心，候选选择会改变后续评测上下文。

已把协议重组为两个层级：

1. `S`（published policy）与 `F`（index-0 policy）均要求完整执行两阶段；`S − F` 只是描述性政策分差，不能自动归因为选择器。
2. 20 / 100 候选池先作为 Stage-1 proposal 诊断，需固定并声明单阶段指标；不称为完整 EPDMS ceiling。
3. 完整候选 oracle `C_N` 暂不定义汇总分，直到 Stage-2 分支、场景复用和聚合映射得到代码级核验。

这将方向 B 当前可检验的部分收窄为“完整政策差异 + 候选分布是否有质量空间”，把无法证明的全管线 oracle 留作后续审计项。
