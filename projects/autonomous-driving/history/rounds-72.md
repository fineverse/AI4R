## 一、采纳：`sota-plan.md` **新增 §10 论文对比协议**

**核心原则**：**表要全、claim 要窄、排除要写理由、自己上榜。** 六小节：

| 小节 | 内容 |
|---|---|
| §10.1 | **先钉死自己的六项口径**（基准划分 / 输入权限 / 输出模态 / 命令维 / **评测器实现版本用官方 `EPDMS` 而非 `EPDMS*`** / 数字来源）→ **这六项上与本题不同的方法不得进主表比分**，这是"合理排除"的唯一依据 |
| §10.2 | **主表 = 官方榜全列 + 标注列、不做挑选**——把"是否经同行评议"做成**表里的一列**，而**不是排除理由**（**表全 → 无挑选嫌疑；列在 → 窄 claim 有依据**） |
| §10.3 | **claim 写三段**（窄主 claim / 诚实的位置说明 / 子榜补强）——**⚠ 本小节的措辞按投递物原文保留，并显式标注"待用户最终确认"** |
| §10.4 | 合法的"排除"**只有五种**，每种都要写理由（特权输入 / 不同划分 / 不同输出模态 / 数字不可核 / **例外：顶会综述详论过的预印本不得排除**） |
| §10.5 | **自己也上官方榜**（成本 = 1 次 POST 或一次提交，审稿人可自查） |
| §10.6 | **投稿前自查 8 条**（含"引用'最高'时区分**榜上最高**与**已发表最高**"——第 69 轮踩过；以及"漏提 concurrent 预印本"是**新颖性风险**，与"是否比"是两件事） |

**整合时做的三处处理**（不是照抄）：
1. **§10.3 标"待用户最终确认"**——投递物自己声明这是唯一待拍板项；
2. **不重复定义"子榜"**——在 §10 开头写明"'子榜'一词只在 [§3](../ideas/sota-plan.md) 定义，本节管**对比集与措辞**"（投递物 §三.4 的提醒）；
3. **不重画基线候选表**——改为在 §10 末尾记一句"**DrivoR 很可能是最强的合法基线**（CVPR 2026 + 有代码 + 在榜 54.574，**但输入协议待核**）"+ 其余四条候选的指针，**避免与 §10.2 的主表两处定义**。

## 二、这一节的定位（为什么值得单列）

§3 解决的是"**怎么切一个可辩护的子榜**"，§10 解决的是"**主表该放谁、claim 该怎么写**"。**两者互补且都服务于同一个目标**（CCF-A 的"可辩护性"）。**§10 的独特之处**：它把**"榜上第 1 名是匿名队"这个尴尬事实**变成**表里的一列**——**不回避，也不被它拖着走**。

## 四、方法论

1. **投递物自己声明的"待确认项"要原样带走、不替用户拍板**——§10.3 是"claim 怎么写"，**它决定了论文的对外说法**，属用户决策。
2. **两个小节讲相邻的事时，先划清边界再写**——§3 与 §10 都涉及"子榜/对比集"，**若不写明"'子榜'只在 §3 定义"，两处会各自定义一遍**（这类"同一概念两处定义"是本空间反复踩的坑）。
3. **重复的表不如一个指针**——投递物 §三.1 那张基线候选表与 §10.2 的主表**信息重叠**，故只留一句结论 + 指针，**没有第二张表**。
