# 第七十四轮：文档体积政策（两线制 + 分档处理）与两份超限文件处理

日期：2026-10-01

## 起因

用户："你自己讨论文件体积**是否需要限制**、**限制的大小**、以及**超出限制的处理办法**"（承接第七十三轮末尾"另起一轮专门处理体积"）。第七十三轮收尾时 `check_links.py` 因两份文件超 64 KiB 而 `exit 1`，且两者都是第七十二轮遗留。

## 三个问题的结论

### 一、是否需要限制：**需要，且是硬约束（有本轮实测证据）**

先在工具上实测：整读 `sota-plan.md`（67 KiB）→ **Read 工具直接失败**：`selected content size exceeds the limit of 64KB`。→ **64 KiB 是 Read 工具一次整读的物理上限，不是"美观约定"**，**不可上调**。超限的后果是"**这个文件从此读不整**"（多段读会丢上下文，正是本工作空间反复出现的"读一半导致 stale"的一类根因）。

### 二、限制大小：**两线制（不再只有一条硬线）**

| 线 | 阈值 | 行为 |
|---|---|---|
| **硬线** | **64 KiB（65536 B）** | **违规**，参与 `check_links.py` 的 exit code；收尾前必须处理（确实修不完的，按 §轮次收尾第 7 步记"已知告警"） |
| **预警线** | **60 KiB（61440 B）** | **只报不阻断**；进入后收尾时须**登记待办或当场处理** |

**为什么要预警线**：原设计只有硬线（等于工具上限、**零余量**），于是文件是**在轮次之间"悄悄"越线**的——`history.md` 每轮必加一行、`sota-plan.md` 每轮追加一节，都是"上一轮还好、这一轮就超"（本轮两份超限文件都是第七十二轮越线的）。

### 三、超出限制的处理办法：**按文件角色分档，不一律拆册**

分册（`X.md → X-2.md`）是**既有唯一手段**，但它有明确代价：**第 28、30 轮共 65 处"拆册后引用没跟改册"**。→ 故按角色分档：

| 角色 | 代表 | 处理 | 理由 |
|---|---|---|---|
| **索引/登记类** | `history.md`、`index.md`、`sources.md`、README | **瘦身**（不拆册） | 价值在"可扫"，**详情已在别处**——`history.md` 的详情本就在 `history/rounds-*.md`，逐字重复才是超限的根因 |
| **脉络/清单类** | `lineage.md`、`transfer.md`、`code/traces/*`、`papers.md` | **拆册** | 按章节组织，拆点自然 |
| **决策/交叉引用稠密类** | `sota-plan.md`、`preparation.md`、`judgments.md` | **优先瘦身去重**；仍超线且找得到"引用最少"的边界时才拆册 | 拆这类文件的引用代价最高（`sota-plan.md` 有 **66 处**跨 §7–§10 引用、分布在 26 个文件里） |

## 落地

- [shared/scripts/check_links.py](../../../shared/scripts/check_links.py) **第 12 项加预警线**（`WARN_BYTES = 60 KiB`，只报不参与 exit code）；docstring 同步为两线制。
- [ai/rules.md](../../../ai/rules.md) §文件更新：阈值条目改写为**两线制 + 分档处理**（唯一事实源）。
- [ai/templates.md](../../../ai/templates.md) §分册约定：加"**分册不是唯一处理**，先按角色分档判断"。
- **`history.md` 瘦身：66 KB → 9.6 KB**（索引类）：各行压缩为一行概览，**信息一字未删**（都在各卷）；顺带修掉原表**被空行切断成多段**、**"49–59 与 60–73 顺序相反"**两处格式问题；并在文末"写新记录的约定"里**落盘"本表是索引、卷是正文"**这条此前只是口头惯例的规则。
- **`sota-plan.md` 去重：67,243 → 65,215 B**（决策类）：把 §7.7.4 / §7.7.5 / §7.7.2 中**与 `judgments.md`·`benchmarks.md` 重复**的长英文原文引用与解释压成"摘要 + 指针"（这些块本就自述"完整版见 benchmarks.md §2.9"）。

## 结果与遗留

- `check_links.py` **exit 0**（死链 0 / 孤儿 0 / 计数 0 错 / inbox 0 / **超限 0**）。
- **两份决策文件仍在预警带**（未超线）：`sota-plan.md` **65,215 B**（距硬线 **321 B**）、`preparation.md` **64,900 B**（距硬线 **636 B**）。→ **下一轮任一追加都可能撞线**。
- **可持续解（未做，记为技术债）**：按分册约定把 `sota-plan.md` 拆为 §1–§6 + §7–§10、`preparation.md` 拆为 §1–§4 + §5–§7；但前者拆点**两侧互相引用**（非"引用最少"边界），本轮判为**成本高于收益**，暂缓。详见 [state.md](../state.md) 待续第 26 项。
