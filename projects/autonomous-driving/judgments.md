- **四种"论文声称 vs 代码实测"的新形态**（第二十三、二十五轮，见 [vla/verification.md §7](topics/vla/verification.md) 与 [verification-2.md §11](topics/vla/verification-2.md)）：① **机制在代码里但被配置全量关闭**——ORION 的 **20 模态扩散消融**（`diffusions.py` 里确为 `ego_fut_mode=20`，但 **7 个 stage 配置全部 `use_diff_decoder = False`**，且无人传 `plan_anchor_path`）→ 论文的扩散对照**不可直接复现**；② **机制只实现了一半**——MindDrive 的 **π_d 只有"速度"是学到的策略**（`sample()`/`argmax` 作用于 meta-action logits），**"路径"是 `torch.argmax(data['ego_fut_cmd'])` 直接取导航命令**；③ **机制根本没发布**——DMW 的 GRPO；④ **机制在代码里且被走到，但训练被冻结而论文未声明**（第二十五轮）——**VaVAM 的 `video_action_model.py:64 self.gpt.requires_grad_(False)` 把 VaViM 冻住**，论文却称"完整 perception-to-action pipeline"、全文无 frozen 字样。→ 前两种只有**读代码**才能发现，第三种只有**查目录树**才会发现，第四种要**同时读论文与代码**才能发现
- **第八类"名字≠实际"陷阱：论文的机制根本不在发布代码里**（第三十六轮追加，见 [sota-plan.md §7.6](ideas/sota-plan.md) 与 [VLA-06 笔记 §代码核验](topics/vla/notes/VLA-06-diffvla.md)）：**DiffVLA（navhard 45.0）** 的官方仓库 `boschresearch/DiffVLA`（36★ / Apache-2.0 / 2025-12-08 最后推送）**README §5 自述**："The released version has some modifications compared to the paper on arXiv: 1. The trajectory head has been updated from **Diffusion Drive** to a self-developed **Transformer-based Trajectory Head**. 2. A **reward loss** derived from multiple EPDM sub-metrics has been introduced."——代码级印证：`navsim/agents/diffvla/` 下**活跃头是 `trajectory_head_reward.py`**，**目录里没有任何扩散轨迹头文件**；`modules/` 只剩 `conditional_unet1d.py` / `scheduler.py` 两件扩散残件；`diffvla_config.py` 的 `diff_loss_weight = 20.0` 仍在但**不被活跃头使用**；配置 `num_voc = 8192`（论文写 N_anchor = 32）。**发布版实为"选优器"**：`RewardHead` 按 **nc/dac/ddc/tlc/ep/tc/lk/hc 八个 EPDM 子指标**各出一个头，损失是 **BCE against 离线 GT 标签**（`pdm_scores_8192`），**推理期**用 `combined_score = w1·cls + w2·nc + w3·dac + w4·(5tc+2lk) + w5·ddc`（**`w = [1.0, 4.0, 1.2, 0.02, 8.0]` 手调常数**）`argmax` 选一条，且 **`ep`/`hc` 算了但没进最终分**。→ **"45.0 = 有代码的纯扩散规划器 SOTA"不成立**（45.0 是论文里带扩散头的竞赛成绩，发布版无公开分数）。**与第七类的区别**：第七类是"机制在仓库里但评测路径 import 了别的版本"，本类是**发布代码里根本没有论文那个机制**（连代码都换了）。→ **凡引用"某方法有代码 + 分数 X"，必须核到"发布版的头/损失/配置是不是论文那套"**；`README` 的 Notifications / 与论文差异段是**必须读的一节**。另：发布版是**"离线 GT 打分监督的选择器"的第 4 个代码级实例**（前三个：WoTE / Drive-OccWorld / World4Drive，见 D 组首条），且候选池 **8192**

### D. 锚点 · 词表 · 选优（12 条）

- **"选优依据"这条路线现有三种代码级核验的实现，且三家都在"选择环节用 GT"**（第二十四轮，见 [C004 §I](code/traces/world_model_code_traces.md)）：① **学到的奖励模型**（WoTE：256 候选 + imitation/五准则打分 + `argmax`）；② **规则 cost volume**（**WM-04 Drive-OccWorld**：世界模型输出的未来占据 → `instance_occupancy`/`drivable_area` → `Cost_Function` → `topk(largest=False)`，cost 用 hinge `relu(gt_cost − sm_cost)` 学；**训练用 GT 占据、推理用预测占据**，且 `planning_steps=1` 逐帧滚动）；③ **世界模型自身的损失**（**WM-07 World4Drive**：`重建+KL+余弦 → argmin`，但**模态分配用 GT 的 FDE**，测试走分类 argmax）。→ **"选择环节依赖 GT"是三家共有的系统性弱点**（OccWorld 的 GT 模式也是同一类），**引用其"多模态"能力时必须标注**。另：**Drive-OccWorld 的规划损失直接抄自 UniAD**（文件头版权声明在，`inter_bbox` 的轴对齐退化一并继承）；**World4Drive `class W4D(VAD)` 继承 VAD**、锚点用同名 `kmeans_plan_6.npy`；**LAW 的 `CD_loss.py` 不是对比蒸馏，是轨迹点损失集合**（已更正）
