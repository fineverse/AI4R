# 世界模型（驾驶侧）发展脉络（2023 → 2026）

更新时间：2026-09-23  
读法：本文件只写**已核验的事实**与**明确标注的判断**；论文编号见 [papers.md](papers.md)（WM-xx）。  
证据等级：基于 **2 篇综述全文**（[2501.11260](https://arxiv.org/abs/2501.11260)、[2502.10498](https://arxiv.org/abs/2502.10498)）+ **9 篇代表工作的全文** + 15 篇的**摘要与元数据**；其中 **5 篇已做代码级静态核验**（WM-01/03/17/18/24），**无运行**。

## 一句话总结

驾驶世界模型的演化是**预测表示的一次次降维**：从"生成看得见的未来"（图像/4D 占据）→ "预测看不见的潜状态"（潜特征）→ "把预测直接接到规划上"。到 2026 年，最有价值的形态不是"世界模型本身多准"，而是**它作为条件喂给规划器时能带来多少提升**。

## 阶段划分

**主分期采用 2502.10498 §3 的"预测空间"五分类**（分界标志＝预测的是什么表示）：

| 阶段 | 时间 | 分界标志 | 代表 | 解决了什么 | 留下什么 |
|---|---|---|---|---|---|
| 1 视觉空间 | 2023–2024 | 预测**像素/视频** | WM-01 Drive-WM（CVPR'24）、WM-02 DriveWorld（CVPR'24） | 让"想象未来"可见、可评价 | 像素级预测与规划目标不直接对齐；算力大 |
| 2 4D / 占据空间 | 2023–2025 | 预测**3D 占据体素随时间的演化** | WM-03 OccWorld（ECCV'24）、WM-04 Drive-OccWorld（AAAI'25）、WM-05 Implicit Residual（ICRA'26） | 表示更接近几何与可行驶区域 | 4D 数据算力开销大；仍不是规划直接需要的量 |
| 3 矢量化空间 | 2023 | 预测**结构化轨迹/智能体状态** | WM-10 TrafficBots（ICRA'23）、WM-11 DriveLaW（CVPR'26） | 与规划接口最直接 | 丢失视觉细节，泛化受限 |
| 4 潜空间 | 2024–2026 | 预测**潜特征**，不解码回像素 | WM-06 Latent WM（ICLR'25）、WM-07 World4Drive（ICCV'25）、WM-08 DLWM（CVPR'26）、**WM-09 DriveFuture** | 省算力；与规划器接口顺 | **潜空间预测难验证**（综述指出需专门的 grounding 机制） |
| 5 多模态 / 统一 | 2025–2026 | 一个模型同时做**理解 + 预测 + 生成 + 规划** | WM-12 DrivingGPT（ICCV'25）、WM-13 UniDrive-WM（ECCV'26） | 消除模块边界 | 训练复杂度与数据需求上升 |

**并行支线：闭环 RL 与"作为条件"**
- **闭环 RL**（WM-14 Think2Drive、WM-15 AdaWM、WM-16 Raw2Drive）：世界模型在**控制回路里**，用于在潜空间想象 rollout 再选动作。**新子类**（第二十四轮）：**WM-23 Imagine-2-Drive 把世界模型当"想象环境"**——DPA 出轨迹 → DiffDreamer 预测该轨迹下的未来观测与奖励 → 回灌 PPO 更新策略，**完全不需要在线交互**。这是"闭环 RL"里唯一**不靠仿真器、只靠学到的世界模型**的一支。
- **作为条件**（WM-09 DriveFuture、WM-17 Policy World Model、WM-18 WorldRFT、WM-19 FutureX）：世界模型**只提供条件**，规划器仍是独立模块。**这条支线对研究对象最重要。**
- **作为选优依据**（第二十四轮补全）：**WM-01 Drive-WM**（命令级：树搜索在 3 个候选命令间选，**无代码可核验**）与 **WM-24 WoTE**（轨迹级：256 条锚 → 世界模型预测每条的未来 BEV → 学到的奖励模型打分 → `argmax`，**已代码核验**）。**这两篇必须区分**——"选优器"的粒度不同，可借鉴的接口也不同。

**世界模型 → 规划器的五条接口路线**（第二十四轮定型，是本文件最可操作的结论）：

| # | 路线 | 未来以什么形式被消费 | 代表 | 证据等级 |
|---|---|---|---|---|
| 1 | **token 级联合自回归** | 未来占据/场景 token 与自车 pose token 在同一序列里交替生成，规划器读自己生成出来的未来 | WM-03 OccWorld、**WM-22 RenderWorld** | OccWorld **代码级**；RenderWorld 全文级 |
| 2 | **隐状态级条件** | 未来帧 token 先占序列，轨迹 query 排其后，规划头读**未来帧之后的隐状态** | WM-17 Policy World Model | **代码级** |
| 3 | **特征级条件** | 池化世界模型的多尺度 UNet 特征 + 历史动作 → MLP 出动作 | **WM-21 DriveDreamer** | 全文级（**代码范围不符，不可核验**） |
| 4 | **选优依据** | 世界模型预测**每条候选轨迹**的未来状态 → 打分 → 选一条。**三种信号**：学到的奖励模型 / 规则 cost volume / 世界模型自身损失 | WM-01 Drive-WM（命令级，无代码）、**WM-24 WoTE**（轨迹级 + 学到的奖励模型）、**WM-04 Drive-OccWorld**（占据 → cost volume → `topk`）、**WM-07 World4Drive**（重建+KL+余弦 → `argmin`，但模态分配用 GT） | WoTE / Drive-OccWorld / World4Drive **代码级** |
| 5 | **RL 的 reward / next-state 来源** | 世界模型当"想象环境"，预测未来观测与奖励，回灌策略梯度 | **WM-23 Imagine-2-Drive**（回灌 PPO）、**WM-16 Raw2Drive**（**reward/continue 由特权世界模型头经 Head Guidance 提供**）、**WM-15 AdaWM**（reward/next-state 取自世界模型，actor-critic 在想象 rollout 里训） | 全文级（**三篇代码都不可核验**：Imagine-2-Drive "Code coming soon"、Raw2Drive 只有 README、AdaWM 无仓库） |

> **读法**：路线 1/2/3/4 的规划器本身**都不是生成式**（OccWorld 是 3 模式 L2 回归、WoTE 是锚 + offset 回归）——**"世界模型进规划器"这件事不要求规划器是扩散的**。路线 5 是唯一把世界模型接进 RL 训练的，**也是五条里唯一"零可核验代码"的**。

**第 6 条：动作专家内嵌在世界模型里**（第二十四轮新增，**已代码核验**）——**WM-11 DriveLaW（CVPR'26）** 的视频扩散 transformer（LTX）里带 `action_expert: true`（`action_in_channels: 3`、`action_num_attention_heads: 16`），训练时 `return_video: false` → **同一个扩散 transformer 里既有视频去噪专家、又有动作专家**，与 **π0 的 action expert 同构**。→ **它不属于路线 1–5**：不是"未来 token 与 pose token 交替生成"（路线 1），也不是"外挂规划头"（路线 3）。**且同一个仓库里还并列了另一条路**（接口 B）：把世界模型隐状态**离线缓存遍 navtrain**，再喂给独立的扩散规划器（`run_training_recogdrive.py` 读 `features['last_hidden_state']`）。→ **"世界模型 + 扩散规划器"这件事已被 CVPR'26 工作做过，且两种接法都在同一仓里**（详见 [C004 §G](../../code/traces/world_model_code_traces.md)）。

**分期分歧（要写明，不抹平）**：另一篇综述（2501.11260 §3）不按"预测空间"分，而按**功能层级**分——生成未来物理世界（Image/BEV/OG/PC）→ 智能体行为规划 → 规划与预测的交互。两者不矛盾但切法不同：前者切"模型内部表示"，后者切"模型在系统中的位置"。**引用时须说明用的是哪一套。**

## 关键转移

### 转移 1：从"看得见的预测"到"看不见的潜状态"（阶段 1/2 → 4）
- **之前**：预测像素或占据体素，可解释、可评价，但与规划目标的距离远。
- **之后**：直接预测潜特征，不解码回视觉空间。
- **判断**：这是**收益最大的一次降维**——省算力，且潜状态天然适合当规划器的条件。代价是**可验证性下降**：潜空间预测对不对，没有直接的评价手段。

### 转移 2：从"世界模型当规划器"到"世界模型当条件"（支线分化）
- **之前**：世界模型在回路里做 rollout，规划由搜索或 RL 完成（闭环 RL 支线）。
- **之后**：世界模型只输出条件，规划交给独立的规划器（"作为条件"支线）。
- **判断**：对研究对象而言，**第 2 条是唯一直接可用的接口**。已有实证：WM-09 DriveFuture 在 NAVSIM v2 navhard 上到 **55.5**（研究对象表 DP-A31，PDF 逐表核对）。**⚠ 第七十一轮更正（同类表述在本文件另有一处，一并改）**：**不能写成"换条件后把 DiffusionDrive 从 24.2 提到 55.5"**——那是把**两个不同方法**（DiffusionDrive 24.2 vs DriveFuture 55.5）的行间差当成了机制收益；第三十五轮已拆开：**24.2 → 30.9（仅 GT 基线，+6.7 归因不明）→ 34.6（+未来条件，+3.7 受控）→ 55.5（+scorer，+20.9 受控）** → **"换条件"的受控收益只有 +3.7**（详见 [judgments.md B 组](../../judgments.md) 与 [sota-plan.md §7](../../ideas/sota-plan.md)）。
- **第二十四轮补充**：代码级核验把这条转移细化成**五条接口路线**（见上文表）。其中**路线 4（选优依据）对研究对象是新增的可借鉴项**——WM-24 WoTE 证明"世界模型给候选轨迹打分"能把 PDMS 从 83.2 提到 85.6（论文 Table 3），而**它的规划器根本不是扩散的**。→ 研究对象侧若要做"世界模型 + 扩散规划器"，**至少有两个不同的接口位**：**把未来当条件喂进去噪（路线 2/3）** 与 **把未来当评价器给采样结果打分（路线 4）**。

### 转移 3：从"单一预测"到"统一模型"（阶段 5）
- **之前**：理解、预测、生成、规划各一个模块。
- **之后**：一个自回归/扩散模型同时做四件事。
- **判断**：目前**只有方法演示，没有证据说明统一比分离更好**；且训练成本与数据需求明显上升。这条对本研究对象**暂不可借鉴**。

## 与研究对象（扩散规划器）的接口差异

| # | 问题 | 结论 | 依据 |
|---|---|---|---|
| 1 | **作为条件还是作为规划器** | **两条路线都存在**，且分化清晰：闭环 RL 支线（WM-14/15/16 + **WM-23**）世界模型在回路里；"作为条件"支线（WM-09/17/18/19）规划器独立；**另有第三条——"作为选优依据"**（WM-01/24），世界模型既不是条件也不是规划器，而是**候选轨迹的评价器**。**研究对象可走"作为条件"与"作为选优依据"两条** | [papers.md](papers.md) 分类列、五条接口路线表 |
| 2 | **潜状态 vs 显式预测** | 五类表示中，**潜空间与规划器接口最顺**（省算力、无需解码），但**难验证**；4D 占据可解释、可评价，但算力开销大。综述把"潜预测的 grounding"单列为问题 | 2502.10498 §3.4 / §6 |
| 3 | **收益来源** | **未验证**。现有证据只有 DriveFuture 的 navhard 24.2→55.5，无法区分收益来自"信息更多"还是"训练信号更好"。**这是可做实验的空白** | 研究对象表 DP-A31 |
| 4 | **代价** | 综述明确把 **Efficiency** 列为限制：4D 数据的算力开销是部署瓶颈；而实时扩散规划器已把预算用满（45–59 FPS）。**世界模型若不能"免费"提供条件，就会吃掉实时性余量** | 2502.10498 §6 |
