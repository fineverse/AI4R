| WM-21 | **DriveDreamer**（ECCV'24） | 两阶段训练：**阶段一** Auto-DM 学交通结构条件（单帧 → 视频，step 1 去掉 temporal attention 加速收敛）；**阶段二**用 **ActionFormer**（GRU + cross-attention 吃动作）在潜空间迭代预测未来交通结构条件 → Auto-DM 联合生成**未来 16 帧视频 + 16 个未来动作**。基座是 **Stable Diffusion v1.4（原参数冻结）**；nuScenes 700 训 / 150 验视频（12 Hz，约 1M 帧），2 Hz 3D box 用 [68] 补到 12 Hz。**规划接口＝特征级**：`pool multi-scale UNet features from Auto-DM` + 历史动作特征 → **MLP 出未来动作**（原文 Eq.10 段）；动作空间是 **yaw 角 + 速度**。开环规划 L2 0.29 m / 碰撞 0.15（Table 3）。**代码核验：`github.com/JeffWang987/DriveDreamer` 只有图像/视频生成侧，未见规划脚本** → 与 WM-01 同类"代码范围不符" |
| WM-22 | **RenderWorld**（ICRA'25） | 纯视觉 E2E：**Img2Occ**（3D Gaussian Splatting 自监督，从 2D 多视角深度+语义图生成 3D 占据标签）→ **AM-VAE**（**两个独立 VQ-VAE 分别编码 air / non-air 体素，各带自己的码本**）→ 自回归世界模型。世界模型**明确沿用 OccWorld 的 masked temporal attention + 多尺度子世界模型 `{w_0..w_K}`**，并**同时解码未来占据与自车位移**（`d_ego(z_0)`，L2 loss）。**规划指标（Table III）**：3D-Occ 输入下 **L2 avg 1.03 m / 碰撞 0.61%**，优于 OccWorld-S（1.17 / 0.60）；**仅用 2D 输入时也优于 OccWorld-S**。**码本消融（Table IV）**：512 最优（mIoU 20.80），1024 反而降到 19.89、256 降到 19.90；**latent 分辨率比码本更关键**（100² 与 25² 都明显更差）。**未找到官方代码仓库** |
| WM-23 | **Imagine-2-Drive**（IROS'25 投稿） | 世界模型 **DiffDreamer** 基于 **SVD**（Stable Video Diffusion）架构、由 **Vista**（约 1700 h 驾驶视频）初始化；关键改动是**一次预测多帧未来观测**（`replace the first P noisy frames with past observations`，把当前帧重复多次拼接以对齐初值）以抑制误差累积，并加一个 **reward 预测头**补齐 MDP。策略 **DPA** 是**扩散策略**（U-Net + **DDIM**），动作是**离散 one-hot 嵌入**（`one-hot embedding of 11 size`，动作空间简化为**局部坐标系下的 Δx/Δy，且固定纵向分量**保证前进）；**用 PPO 在 DiffDreamer 的"想象空间"里更新**（无需在线交互）。评测 CARLA Town04 v0.9.11，20 Hz，10 个场景。**Table I**：SR **83.33%** / Infraction **0.70 /km** / RC **82.13%**，vs Dreamer-V3（63.33 / 1.52 / 67.53）。**一处自相矛盾**：摘要写 "Route Completion and Success Rate by **15% and 20%**"，正文写 "**20% and 14.6%** improvement in SR and RC" → **RC 15% vs 14.6% 不一致**。**代码未发布**（README "Code coming soon!"） |
| WM-24 | **WoTE**（ICCV'25） | **选优器形态的第二个实证，且是第一个可代码核验的**。三段式：① **Trajectory Predictor**：K-Means 出 **N=256** 条轨迹锚（论文 §4.2 原文 `We use N = 256 trajectory anchors`）；② **Trajectory Refinement**：锚经 MLP 编码成 query，与当前 BEV 做 cross-attention，MLP 头出 **offset**，`锚 + offset = 精修轨迹`；③ **BEV World Model + 奖励模型**：世界模型预测**每条候选的未来 BEV**，奖励模型给分选优。奖励 = **imitation（锚到专家轨迹 L2 距离的负值 softmax）+ simulation（NC/DAC/EP/TTC/Comfort 五准则）**；**训练需真值**（nuPlan 模拟器给 BEV 语义图与规则奖励），**推理不需**。**Table 3 消融证明"未来状态进入奖励模型"是增益来源**：无评估 81.0 → 有评估但用当前状态 83.2 → 加入未来状态 **85.6**。**延迟 18.7 ms（L20，256 轨迹）**；Table 6 显示 64→128 提升显著、128→256 收益递减。**Bench2Drive**：以 **TCP** 为基线接入评估模块，Driving Score **+1.81**。**代码核验：256 锚 / 学习到的奖励模型 / `argmax` 选优 / 8 poses@2 Hz 全部成立**，但**默认配置只跑 1 步世界模型**（`num_fut_timestep = 1`）与论文的"两步（t+2s/t+4s）"不符，见 [C004 §E.1](../../code/traces/world_model_code_traces.md) |

### 4.2 第二十五轮新读全文的 2 篇（WM-15 AdaWM、WM-16 Raw2Drive）

两篇均为**摘要级升全文**，且都做了代码可用性核验（**均为负面结论**）。**这两篇合起来把"世界模型 → 规划器"的接口路线补全到"⑤ RL 的 reward / next-state 来源"有了第二个实例**（第一个是 WM-23 Imagine-2-Drive，代码未发布）。

| 编号 | 论文 | 本轮读到的关键新增事实 |
|---|---|---|
| WM-15 | **AdaWM**（ICLR'25） | **Dreamer v3 式 RSSM 潜动力学**（encoder-decoder + RSSM），预测对象是 **BEV 语义图的潜状态**（**不是像素视频**）；规划器是 **Dreamer v3 actor-critic，在想象 rollout 中训练** → **非生成式**（无扩散、无采样选优）。**"adaptive" 的含义只是"微调调度"**：用 **TV 距离**估计"动力学模型失配"与"策略失配"，**择大者更新**（模型用 **LoRA / NoLa 低秩**、策略用**子单元凸组合权重**）→ **不是结构自适应**。**接口位 = ②隐状态级条件**：actor/critic 以 model state（`h_t` + 随机潜态）为条件，value 用 n 步 lookahead 回报，**reward / next-state 取自世界模型 reward 头与潜动力学** → **世界模型确被规划器消费**。**数字**：**无 nuPlan / nuScenes**，用 CARLA 自定义 TTC/SR 口径——**ROM03 2.05 / 0.82 vs DreamerV3 0.95 / 0.40**、LTD03 1.92 / 0.70 vs 0.15 / 0.35、Pre-RTM03 与 DreamerV3 同为 1.16 / 0.68；**未与 DiffusionDrive / TransFuser 比**。**消融只有微调策略对照**（No / P-only / M-only / M+P / AdaWM）→ **无"去掉世界模型"对照**。**输入权限：BEV 语义分割 128×128，由 CARLA 特权信息 + 地图拓扑构造**；离散动作 accel{-2,0,2} × steer{-0.6,-0.2,0,0.2,0.6}；**训练与推理同用特权 BEV → 特权泄漏到推理侧**（与 WM-16 的"特权仅训练侧"形成对照）。**代码：无官方仓库**。**可疑点**：① 正文称 ROM03 为"环岛"，配置实为 `NoScenario_Town03`；② **基线不微调，比较不对称**（作者自述）；③ 仅 4–5 个任务、**单次运行、无种子/方差**；④ Reproducibility 称"将提供"却无链接 |
| WM-16 | **Raw2Drive**（NeurIPS'25） | **双流 MBRL：两套 Dreamer v3 式 RSSM 世界模型 + 两套 actor-critic**。特权流 = **时序 BEV 语义掩码（43 通道）**；原始流 = 多视角 RGB + IMU，经 **BEVFormer** 编码为网格 BEV 特征。**对齐方式非对抗、非对比**：**Spatial-Temporal Alignment Loss**（encoder state 用 L2）+ **Abstract-State Alignment**（deterministic 用 L2、stochastic 用 **KL**）；且 rollout **只从原始流采样一次**喂入两流以消累积误差。**RL 算法是 Dreamer v3 actor-critic，不是 PPO / SAC**。**接口位同时命中两条**：**②隐状态条件**（原始策略在原始世界模型内 rollout 训练，隐态条件 + 想象回报）+ **⑤RL 的 reward / next-state 来源**（**reward / continue 由特权世界模型头经 Head Guidance 提供**）；另把特权策略的**动作分布蒸馏**至原始策略。**数字**：**Bench2Drive 闭环 DS 71.36 / SR 50.24**（同表 UniAD 45.81 / 16.36、DriveTrans 63.46 / 35.01、**特权 Think2Drive 91.85 / 85.41**）；**CARLA v2 leaderboard val/devtest 仅 DS 4.12 / 3.56、RC 9.32 / 6.04、IS 0.43 / 0.42**。**消融（Dev10，3 次平均）**：rollout guidance 全缺 **DS 0.0**、Spatial+Temporal 全缺 **DS 0.0**；**直接沿用特权策略 58.4 vs 微调 83.5**（间接证明原始世界模型对策略有边际收益）；**无"完全去掉世界模型"对照**。**输入权限：训练用特权、推理仅原始**——原始流 = 环视 RGB + IMU，**相机路数 / 分辨率 / 帧率 / 历史帧均未给出**；特权流 = 43 通道 BEV 掩码 + 自车向量 + GT 框 + HD-Map；39 离散动作。**代码：`Thinklab-SJTU/Raw2Drive` 仅 2 commits、文件树只有 `README.md`（321 B）**，内容仅标题 + "Official inference code" 一行 → **README 称有推理代码但仓库 0 代码**。**可疑点**：① 上述 README 名实不符；② **leaderboard DS 仅 4.12 / 3.56 却称"CARLA Leaderboard 2.0 唯一 RL E2E 方法"**，其 SOTA 只在 raw-sensor E2E 子集成立；③ 消融用 10-clip Dev10，**DS 83.5 与主表 71.36 口径不同** |

**世界模型侧已无摘要级条目**——24 篇全部读过全文（见 [papers.md](papers.md) §4；**2026-09-24 更正**：此前记"剩余 8 篇为摘要级"已不成立）。

**这两篇带来的两条判断**：
1. **"世界模型 → 规划器"的第 5 条路线（RL 的 reward / next-state 来源）现在有两个实例，但两篇都没有可核验代码**（WM-23 Imagine-2-Drive "Code coming soon"、WM-16 Raw2Drive 只有 README）→ **这条路线目前是五条里唯一"零代码证据"的**。
2. **"特权信息"在世界模型侧的用法出现分叉**：**WM-15 AdaWM 把特权 BEV 泄漏到推理侧**（训练与推理同用 128×128 语义分割），而 **WM-16 Raw2Drive 严格限定在训练侧**（推理只用环视 RGB + IMU）→ 与 [benchmarks.md §2.5](../../direction/benchmarks.md) 的"输入权限硬边界"合起来看，**引用这两篇的世界模型收益时必须先问"推理侧是否仍吃特权"**。

### 4.3 第二十五轮第二批新读全文的 3 篇（WM-02 DriveWorld、WM-10 TrafficBots、WM-11 DriveLaW）

| 编号 | 论文 | 本轮读到的关键新增事实 |
|---|---|---|

**本批带来的三条判断**：
1. **"世界模型收益"的量化证据从 1 条增加到 3 条，且口径都是"同一规划器换输入"**：**DriveLaW Table 5 +5.0 PDMS（BEV → 视频潜状态）**、**World4Drive Table 3 去 WM 后 L2 劣化 18.0% / 碰撞劣化 55.6%**、**IR-WM Table V 不用未来 BEV 时 L2 0.53 → 0.87（+0.34 m）**；再加 Think2Drive 的"model-free PPO 57.5 → 有世界模型 83.8"（**但这条是跨方法比较、不是同一规划器换输入**）。→ **"世界模型确实带来收益"现在有三条独立证据，且量级都不小**——**这与"生成机制 / 条件"两维的 +3 ~ +5 相比，世界模型这一维的收益可能更大**（但**三篇的基准与指标各不相同**，不能直接横比）。
2. **但"世界模型"这个机制的内部差异被回避了**：**IR-WM 的核心卖点是"残差"，却恰恰没有"去掉残差"的消融**（且代码里那行加法挂着 `# TODO: predict residual bev features`）；**Drive-OccWorld 与 DrivingGPT 都没有"去掉世界模型"的消融**；Think2Drive 没有"去掉潜空间想象"的消融。→ **本轮读的 5 篇里，只有 World4Drive 一篇把"世界模型的有无"做成了表内的受控行**（Table 3 行 5 vs 行 6）。
3. **"自车状态"这一维在规划器里被大量剔除，且论文会主动声明**：**IR-WM 的 Table IV 明确注 "The ego status was not utilized in the planning module"**、**DrivingGPT §4.4 显式排除自车状态**、**Drive-OccWorld 只有 ‡∗ 协议才用**。→ 与 [benchmarks.md §2.5](../../direction/benchmarks.md) 的"输入权限硬边界"一致：**NAVSIM 侧自车状态是标准输入，nuScenes 侧的这些工作却主动不用** → **跨基准比较时"自车状态"要单列一维**。

| **`ReCogDriveDiffusionPlanner`** | `video_models/planner/diffusion_planner.py`(41,923 B)、`lightningdit.py`(9,009 B) | **一个完整的扩散规划器**（`config_class = ReCogDriveDiffusionPlannerConfig`） |
| **DiffusionDrive 基线** | `navsim/agents/diffusiondrive/`（`transfuser_model_v2.py` 22,659 B 等） | 作者**在同一仓里保留了 DiffusionDrive 作为对照** |

**两条并行的"世界模型 → 规划器"接口**（本工作空间首次见到同仓并列）：

- **接口 A（默认路径，`VideoDriveAgent`）**：**动作专家长在视频 transformer 内部**——`action_expert: true`、`action_in_channels: 3`、`action_num_attention_heads: 16`；`train_mode: 'action_full'`、**`return_video: false`**（训练只出动作）；`num_inference_step: 5`。→ **与 π0 的 action expert 同构**，是"世界模型即规划器"的实现，属**五条接口路线之外**。
- **接口 B（`recogdrive` 路径）**：README Step 1 把**世界模型隐状态**缓存遍 navtrain，`run_training_recogdrive.py` 的 `custom_collate_fn` **直接读 `features['last_hidden_state']`** → 隐状态就是规划器唯一的感知条件。**但 `navsim/agents/` 下没有 `recogdrive/` 目录** → `recogdrive_agent.yaml` 的 `_target_` 是**死引用**，`ReCogDriveAgent` **未随仓库发布**。

**`ReCogDriveDiffusionPlannerConfig` 实测字段**：`action_horizon = 8`（NAVSIM 8 路点）、`sampling_method = 'ddim'`、**`num_inference_steps = 5`**、`hidden_size = 1024`、`input_embedding_dim = 1536`；**三种采样路线 `flow` / `ddpm` / `ddim` 并列**；**`grpo = False`（默认关闭，与 ORION 的 `use_diff_decoder = False` 同类）**，而 `grpo_cfg.scorer_config` 是 **`PDMScorerConfig(progress_weight=10.0, ttc_weight=5.0, comfortable_weight=2.0)` + `metric_cache_path` + `reference_policy_checkpoint`** → **RL 奖励是真 PDM scorer**（"RL 词义核验"清单里最强的一档）。

> **对研究对象的意义**：**"视频世界模型 + 扩散规划器"这条路已被 CVPR'26 工作走通，且两种接法都试过**（专家内嵌 / 隐状态外挂）。→ 研究对象若做同一件事，**"接在哪一层"的选择空间已被前人穷举**；真正剩下的空白是**收益来源拆解**。
