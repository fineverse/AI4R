## 2. 三条判断

1. **V3 的驱动力是"频率"，不是"多模态"**：V2 的瓶颈是 **AR 单步只有 3–5 Hz**（OFT 论文原文 "too slow for 25-50+ Hz"）；V3 的两条解法——**并行解码 + 连续回归**（OFT）与**动作块 + 流匹配**（π0）——**都是冲着频率去的**。→ **具身侧"从离散 token 转向连续头"的理由与驾驶侧"从回归转向扩散"的理由不同**：**前者为快，后者为多模态**。
2. **π0 是分水岭，且它的影响是"动作专家内嵌"而非"换动作头"**：π0 之后新增的流匹配工作（FLOWER、SmolVLA、GR-3）**都是 VLM 与动作专家分离或半分离**的架构；这套结构后来被直接搬进驾驶（DriveMoE 以 π0 为底座、DriveLaW 的 `action_expert`）。→ **具身侧对驾驶侧最有价值的输出是"动作专家内嵌"这个结构**，不是某个具体动作头。
3. **"扩散 vs 回归"在具身侧没有统一结论，且证据方向与驾驶侧相反**：**OpenVLA-OFT 证明连续 L1 回归 ≈ 扩散且更快**；**RDT-1B 的 `regress` 变体去掉扩散后大幅掉分**（真机 50→12.5 / 62.5→50 / 100→12.5）；**FLOWER 直接做了 flow / L1 / 离散 token 三路对照**。→ **依任务而定**；而驾驶侧 **SpanVLA 的"回归头 → flow matching"是 +5.2 PDMS**（受控）。**引用"扩散更好"时必须注明是哪一侧、哪个任务**。

## 3. 与驾驶侧同名小方向的关系

- **结构可搬**：动作专家内嵌 / 动作块 / 并行解码。
- **语义不可搬**：具身是"高维瞬时关节动作（7–32 维）"，驾驶是"低维长序列轨迹（2–3 维 × 8–80 步）"。见 [大方向脉络 §3.1](../../direction/lineage.md)。
- **安全层不可搬**：具身的硬约束只在低维 toy 域有实现，驾驶的失败代价是碰撞归零。见 [§3.3](../../direction/lineage.md)。

## 4. 继承关系（论文 / README 级，无代码核验）

本小方向"写判断、事实见 [papers.md](papers.md)"，故本节只写**血统判断 + 指针**。强度分级 S1–S4 见 [workflows.md §代码脉络梳理](../../../../ai/workflows.md)。

- **V1 → V2 → V3 是一条继承链**：**RT-2**（把动作当文本 token）→ **OpenVLA**（把"VLM 底座 + 动作 token"开源化）→ **π0**（改用流匹配动作专家，分水岭）。
- **V3 内部两条解法同源不同路**：**π0 的"动作块 + 流匹配"** 与 **OpenVLA-OFT 的"并行解码 + 连续 L1 回归"**，二者都针对 V2 的 AR 单步瓶颈（见 §2 判断 1）。
- **π0 之后的流匹配工作多为同源派生**：**FLOWER / SmolVLA / GR-3** 都是"VLM 与动作专家分离或半分离"的架构（见 §2 判断 2）。
- **对驾驶侧的血统输出**：**DriveMoE 以 π0 为底座**、**DriveLaW 的 `action_expert` 与 π0 同构**（见 §3 与本项目 [大方向脉络 §5](../../direction/lineage.md)）。
