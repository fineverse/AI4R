# 文献质量分档

更新时间：2026-09-23  
用途：判断一篇文献**值不值得读**，与 [ai/rules.md](../ai/rules.md) 的「证据等级」（我读到了什么程度）配对使用。  
适用范围：所有项目的文献检索任务。领域白名单当前只覆盖**自动驾驶 / 机器人 / 计算机视觉**，其他领域需另建。

## 1. 要解决的问题

预印本没有 venue、没有引用，无法用常规指标衡量；而恰恰是最近 12 个月的工作最需要判断。**引用数对 <12 个月的工作天然无效**——不是质量差，是还没时间被引用。

因此本规范**不给文献算分，只分档 + 标注可复核依据**。

## 2. 第一步：把「假预印本」救出来

很多"预印本"其实已录用，只是 arXiv 版本没更新。核验顺序：

1. **arXiv `comments` 字段**——常直接写 "CVPR 2026" / "Accepted to ICLR 2026"
2. **OpenAlex 是否有非 arXiv 记录**——有则取正式 venue 与引用数
3. **会议官网接收列表**

救回来后直接进入"已发表"通道（T1）。

## 3. 四类信号

| 信号 | 已发表 | 预印本 | 获取方式 |
|---|---|---|---|
| venue / CCF 评级 | ✅ 直接查 | ❌ 缺失 | [shared/ccf/](ccf/ccf-2026-all.json) + 本文件 §5 白名单 |
| 引用数 | ✅ | ⚠️ **无效**（<12 个月） | OpenAlex 按标题检索，取非 arXiv 记录最大值 |
| **同行采纳** | ✅ | ✅ **最有用** | 被顶会/顶刊综述**详细讨论**，或被同期顶会工作**直接对比** |
| 团队 / 作者 | ✅ | ✅ 唯一可用先验 | OpenAlex 查作者近 3 年顶会论文数 |

**引用数只作 >2 年工作的分水岭。**

## 4. 分档

| 档 | 判据 | 处理 |
|---|---|---|
| **T1** | 已发表，venue 在 CCF 目录或 §5 白名单 | 入选，标注评级 |
| **T2** | 预印本但**核实到已录用**（§2 任一条成立） | 等同 T1 |
| **T3** | 预印本，被 2025–2026 顶会/顶刊综述**详细讨论**，或被同期顶会工作**直接对比** | 可作代表工作 |
| **T4** | 预印本，已知强团队 **且**（有官方代码 **或** 方法明显独特） | 入选，标注"仅预印本" |
| **T5** | 其余 | **不收录**，最多进「边界外清单」 |

**两条硬约束**：

1. **T4 必须"团队 +（代码 或 独特性）"**，不能只看团队——否则是纯光环效应，会系统性漏掉小团队的好工作。
2. **区分"详细讨论"与"列一行"**。综述有覆盖导向的动机，把弱工作也列进表是常态；只有被正文详细讨论（有篇幅、有分析）才算 T3。

## 5. 领域白名单

CCF 目录对本领域**覆盖不全且评级与领域认知不符**（实测：ECCV 只给 B、IROS 只给 C；CoRL / RSS / WACV / IEEE IV / ITSC / TIV / RA-L / IJRR / TMLR 完全不在目录内）。因此叠加以下白名单，**冲突时以白名单为准并注明**。

| 类别 | 清单 |
|---|---|
| 会议 | CVPR、ICCV、ECCV、NeurIPS、ICLR、ICML、AAAI、IJCAI、CoRL、RSS、ICRA、IROS、WACV、ACM MM、IEEE IV、ITSC |
| 期刊 | TPAMI、IJCV、TITS、TIV、RA-L、TR、TNNLS、TIP、IJRR、TMLR |

白名单是**下限**（不在名单内的不等于差），用于快速判断；边界情况回到 §3 的四类信号。

## 6. 核验流程

1. arXiv `comments` → 是否已录用
2. OpenAlex 是否有非 arXiv 记录 → 取正式 venue 与引用
3. 查 `shared/ccf/ccf-2026-all.json` + §5 白名单 → 得评级
4. 仍无 venue 的 → 查作者团队近 3 年顶会数
5. 仍不确定的 → 查是否被综述详细讨论 / 被同期工作直接对比
6. 把结论写进表格的「质量依据」列

**CCF 查询注意**：简称需 `str.upper()` 后匹配；部分条目（如 NeurIPS）用全称子串匹配更稳。参考 [ccf/README.md](ccf/README.md) 的 `rating()` 示例。

## 7. 表结构约定

论文表新增「质量依据」列，写**可复核的事实**，不写分数：

```
| 编号 | 论文 | 年份 | venue / CCF | 引用 | 机制或输出 | 质量依据（T 档 + 具体信号） |
```

示例：

- `T1：AAAI'26（CCF-A）`
- `T3：被 VLA4AD 综述 §4.2 详细讨论；仅预印本`
- `T4：团队 Wayve；有官方代码；仅预印本`

**为什么给依据而不给分数**：任何人都能顺着依据复核，也能一眼看出哪条是弱证据；黑箱分数无法复核，也无法暴露"这条其实是靠团队光环进来的"。

## 8. 已知风险

1. **综述收录 ≠ 质量**——只算"进入领域视野"。
2. **团队信誉有光环效应**——所以 T4 要求"团队 + 代码/独特性"双条件。
3. **白名单是下限不是上限**——不在名单里的好工作要靠 §3 的同行采纳信号捞回来。
4. **引用数会变**——写入表格时标注快照日期。
